The fourteen cross-cutting concerns are each specified as a component-style spec in `docs/spec/ordin-desktop/cross-cutting/` (template: `component-spec-template.md`, greenfield, no classification tags). The set is split into one file per concern because together the files exceed 4,000 lines (5,054). Thirteen concerns come from `cross-cutting-concerns.md`; the fourteenth, *Licence check*, is added for the build rule of HLD 05 (*Licence and vulnerability checks*). Per-program applicability is binding from Phase 1A SA-XC-01 to SA-XC-13 and is restated in each file's *Applicability by program* table.

## Error-code registry

`cross-cutting/ErrorHandling.md` § *Error-code registry* holds **2,008 codes owned by 78 component specs** (*amended January 2026, ADR-112 and ADR-113: 50 codes added, among them the new prefixes `KQ_` (Knowledge Query Client and Server, 20) and `KRD_` (Knowledge Reader, 13); the count before this amendment was 1,958 rows, counted from the registry on January 2026; amended January 2026, ADR-107: 9 codes added, `MPOL_PROVIDER_NOT_READY` removed; ADR-106: 25 codes and the Jira Adapter added; ADR-104: 5 codes from the Knowledge and File Services; ADR-103: 28 codes and the Team Knowledge Service added; ADR-102: 66 codes and the Slack Service added*), regenerated on January 2026 from the corrected component specs and the Phase 2C files rather than from the earlier table (audit-checklist error-code item): 1,632 codes from the Error Tables' *Code* column (1,819 rows: 1,718 plus 73 added on January 2026, ADR-102, and 28 added on January 2026, ADR-103; plus the 5 codes of the ADR-104 amendments' added rows), 199 Phase 2C validation codes the owners copy, 29 Phase 2C validation codes no component copies (registered under the crate that owns the prefix or checks the 2C entity), and 3 codes chosen in a component's validation table. Each row gives code, owner, surface (Service API, Remote API, Caller API, hook, MCP tool, internal), HTTP status, retryability, a one-line meaning and its source. The prefix → owner table is in the same file; every prefix has 2–6 letters; wrightrun's carried codes keep their names (D8), and `SRV_` is shared by wrightrun's carried codes, the Remote API's routing refusals and `SRV_BAD_CURSOR`.
